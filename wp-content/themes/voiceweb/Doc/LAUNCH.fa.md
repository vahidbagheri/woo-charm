# آماده‌سازی انتشار آوان چرم

تاریخ: **۲۱ نوامبر ۲۰۲۶**. دامنهٔ اعلام‌شدهٔ مالک: **https://avancharm.ir**؛ کنترل‌پنل: **cPanel**. این مرحله روی نصب محلی انجام شده و به معنی آپلود یا انتشار روی هاست نیست.

[راهنمای اصلی](README.fa.md) · [کش و قطع فوری](CACHE.fa.md) · [اجرای پروژه](RUNBOOK.fa.md) · [برنامهٔ سئو](SEO-ROADMAP.fa.md)

## سنجش ثبت‌شده

Lighthouse **13.0.1**، نشانی HTTPS محلی، تنظیم استاندارد موبایل و preset دسکتاپ، کش صفحهٔ مهمان گرم و کش مرورگر تازه؛ ۲۱ نوامبر ۲۰۲۶:

| حالت | عملکرد | دسترس‌پذیری | Best Practices | SEO |
|---|---:|---:|---:|---:|
| موبایل | **۹۹** | **۱۰۰** | **۱۰۰** | **۱۰۰** |
| دسکتاپ | **۱۰۰** | **۱۰۰** | **۱۰۰** | **۱۰۰** |

در موبایل FCP برابر ۱٫۲ ثانیه، LCP برابر ۲٫۰ ثانیه، TBT و CLS برابر صفر بودند. خط مبنای موبایل پیش از تغییرها **۶۶ / ۹۶ / ۷۸ / ۶۹** و LCP حدود ۷٫۶ ثانیه بود. عملکرد موبایل در اجراهای توسعه نوسان داشته و هنوز امتیاز ۱۰۰ آن ادعا نمی‌شود. سنجش پس از انتقال به هاست واقعی لازم است. گزارش‌های کامل در پوشهٔ موقت `voiceweb-launch-2026-11-21` با نام `final-mobile.report.html` و `final-desktop.report.html` ثبت شده‌اند؛ این فایل‌های آزمایش به هاست منتقل نمی‌شوند.

آزمون‌های تکمیل‌شده: ۴۰ بررسی قیمت‌گذاری، ۱۵ بررسی پایان sale، ۳۰ بررسی سئوی فروشگاه؛ آزمون HTTP خانه/محصول/دسته، noindex و عدم HIT صفحه‌های خصوصی و آرشیو قدیمی، ریدایرکت HTTPS، نقشهٔ سایت و JSON-LD؛ آزمون مرورگر تقویم شمسی، اولویت عددی، تغییر تنوع، زمان سرور، چیدمان کارت و انقضای واقعی؛ و آزمون تک‌فایل کش همراه شروع/پایان sale، تغییر محتوا/ACF/asset و ثابت‌ماندن موجودی. صفحهٔ اصلی در عرض‌های ۳۲۰ تا ۱۴۴۰، جست‌وجو، منوی موبایل، فوتر و حالت بدون JavaScript نیز بررسی شده است.

## وضعیت آماده‌شده

- نشانی محلی `https://woo-charm-main.local` با گواهی معتبر فعال است؛ `home` و `siteurl` و لینک‌های محتوایی به HTTPS منتقل شده‌اند. `blog_public=1` است تا انتشار نهایی قابل ایندکس باشد. این دامنهٔ محلی در اینترنت عمومی در دسترس گوگل نیست.
- `robots.txt` نقشهٔ سایت نهایی `https://avancharm.ir/wp-sitemap.xml` را معرفی می‌کند. پس از انتقال، خروجی واقعی آن URL نیز باید بررسی شود.
- قواعد ریدایرکت HTTP دامنهٔ اصلی، HTTPS، کنتراست، نام دسترس‌پذیر لوگو، اندازهٔ تصاویر، CSS اولیه، defer اسکریپت‌های خانه و کش مرورگر اصلاح شده‌اند. قالب برای crawler یا Lighthouse پاسخ متفاوت تولید نمی‌کند.
- فونت کوچک آیکون خانه با `tools/build-icon-subset.py` از فونت فعلی ساخته شده؛ فونت کامل برای نویسه‌های دیگر برقرار است و تغییر فایل فونت اصلی، مسیر subset را خودکار غیرفعال می‌کند. ابزار build به `fonttools[woff]` نیاز دارد؛ سرور وردپرس به Python نیاز ندارد.
- فونت‌های Dana خانه با حفظ تمام نویسه‌ها و شکل‌های اتصال توسط `tools/build-display-fonts.py` سبک شده‌اند؛ فایل‌های اصلی برای بقیهٔ صفحه‌ها حفظ شده‌اند. جزئیات preload و fallback در [FONTS.fa.md](FONTS.fa.md) است.
- بنر اصلی پنج اندازهٔ AVIF دارد و اندازهٔ درخواست‌شده با عرض واقعی تصویر تطبیق داده شده است. WebP و فایل اصلی حفظ شده‌اند. با تغییر تصویر ACF یا فایل اصلی، مسیر اختصاصی AVIF برای آن تصویر خودکار کنار می‌رود. برای بازسازی از `tools/build-hero-avif.cjs` با بستهٔ build به نام `sharp` استفاده کنید؛ این بسته در زمان اجرای وردپرس لازم نیست.
- برای **۵۹ محصول کاتالوگ** توضیح کوتاه یکتا، دو پاراگراف معرفی اختصاصی، راهنمای هماهنگی سفارش و لینک دسته ثبت شده است. ابعاد، ظرفیت، نوع چرم هر مدل، ضمانت و امتیاز ساختگی اضافه نشده‌اند. متن‌ها از محصولات وردپرس قابل ویرایش‌اند.
- متن قبلی هر محصول در `_voiceweb_launch_copy_backup` ذخیره شده است. اجرای دوبارهٔ ابزار، متنِ قبلاً آماده‌شده یا ویرایش بعدی مدیر را بازنویسی نمی‌کند.
- ۸۶ نوشتهٔ قدیمی نامرتبط گردشگری و ۴۲۰ دسته/برچسبِ فقط متعلق به همان آرشیو در دو زبان، با نسخهٔ پشتیبانِ وضعیت قبلی، `noindex` و از نقشهٔ سایت بومی خارج شده‌اند. مجلهٔ چرم و دسته‌های فروشگاه برقرارند. فهرست هدف در `voiceweb_launch_index_manifest` ثبت شده تا اجرای دوباره، نوشته‌های آینده را انتخاب نکند. محتوا و نشانی‌ها حذف نشده‌اند.
- [کش مستقل](CACHE.fa.md) با یک فایل قطع می‌شود و ذخیرهٔ محتوای فروشگاه، نسل قبلی را نامعتبر می‌کند.

برای بازسازی assetهای بهینه، ابزارهای build را در پوشهٔ موقت نصب کنید؛ از ریشهٔ وردپرس:

```powershell
python -m pip install --target "$env:TEMP/voiceweb-fonttools" 'fonttools[woff]'
$env:PYTHONPATH="$env:TEMP/voiceweb-fonttools"
python wp-content/themes/voiceweb/tools/build-display-fonts.py
curl.exe --noproxy '*' -s https://woo-charm-main.local/ -o "$env:TEMP/voiceweb-font-source.html"
python wp-content/themes/voiceweb/tools/build-icon-subset.py "$env:TEMP/voiceweb-font-source.html"
npm install --prefix "$env:TEMP/voiceweb-launch-media-tools" --no-audit --no-fund sharp
$env:VOICEWEB_SHARP_PATH="$env:TEMP/voiceweb-launch-media-tools/node_modules/sharp"
node wp-content/themes/voiceweb/tools/build-hero-avif.cjs
```

سورس SCSS تغییرکرده نیز باید به CSS متناظر کامپایل شود. فایل‌های تولیدی `display`، `iconly`، AVIF و JSONهای امضا همراه قالب منتقل شوند. در خانه و بقیهٔ صفحه‌ها، URL فونت Iconly نسخهٔ فایل را دارد تا تغییر فونت افزونه پشت کش یک‌ساله باقی نماند.

## انتقال واقعی به cPanel

۱. از فایل‌ها و دیتابیس کامل فعلی backup بگیرید. **دیتابیس و رسانه‌ها را همراه قالب و افزونه‌ها منتقل کنید**؛ توضیحات، ACF، دسته‌ها و منوها داخل دیتابیس‌اند. فقط کپی قالب برای انتقال فروشگاه کافی نیست. `wp-content/cache/voiceweb-pages/` را منتقل نکنید.

۲. در cPanel دامنه را به پوشهٔ درست متصل و SSL معتبر AutoSSL را برای `avancharm.ir` و در صورت استفاده `www` فعال کنید. PHP و افزونه‌های لازم ووکامرس و ماژول‌های هدر/فشرده‌سازی را بررسی کنید. اتصال دیتابیس مقصد را در `wp-config.php` تنظیم کنید. مقادیر محیط محلی، مسیرها، رمزها و saltها را بدون بررسی روی هاست کپی نکنید. مقدار `WP_ENVIRONMENT_TYPE` در مقصد **`production`** باشد.

۳. فقط در نصب مقصد، از Terminal و ریشهٔ وردپرس پیش‌نمایش و سپس اعمال تغییر دامنه را اجرا کنید:

```sh
php wp-content/themes/voiceweb/tools/prepare-launch.php --production
php wp-content/themes/voiceweb/tools/prepare-launch.php --production --apply
```

این ابزار روی محیط `local` اجازهٔ انتقال به دامنهٔ عمومی نمی‌دهد. تنظیمات قبلی نشانی و نمایش در موتور جست‌وجو backup می‌شوند؛ لینک‌های نوشته، متا و تنظیمات ACF/قالب با API وردپرس و حفظ دادهٔ سریال‌شده تبدیل می‌شوند. GUID، سفارش‌ها و داده‌های پرداخت تغییر نمی‌کنند. اگر مهاجرت دیگری پیش‌تر دامنه را تبدیل کرده، وجود URLهای محلی در جدول‌های سفارشی افزونه‌ها و تنظیمات اختصاصی سرویس‌ها را هم بررسی کنید؛ این ابزار جایگزین مهاجرت تمام جدول‌های سفارشی نیست.

۴. پیوندهای دائمی را یک بار از مدیریت ذخیره کنید. روی مقصد، HTTP باید به HTTPS و `www` به نشانی canonical تعیین‌شده برسد. صفحهٔ اصلی، یک دسته، یک محصول، نقشهٔ سایت، robots و نبود mixed content را با مرورگر بدون ورود بررسی کنید. canonical و آدرس‌های دادهٔ ساختاریافته باید `avancharm.ir` باشند.

۵. روش خرید، قیمت، نرخ دلار، موجودی، مشخصات واقعی هر محصول، شرایط ارسال/بازگشت و شماره تماس را برای فروش واقعی تأیید کنید. بخش قابل توجهی از کاتالوگ فعلی در حالت درخواست تماس است؛ این تنظیم عمداً به خرید آنلاین تبدیل نشده است. سرویس پیامک، ایمیل، callback درگاه و یک سفارش کنترل‌شده روی هاست نیاز به آزمون واقعیِ صاحب سرویس دارند؛ این مرحله هیچ پیامکی یا پرداخت واقعی ایجاد نکرده است.

۶. Lighthouse موبایل و دسکتاپ را روی دامنهٔ واقعی دوباره اجرا کنید؛ هاست، شبکه و افزونه‌ها نتیجه را تغییر می‌دهند. دامنه را در Search Console تأیید و `https://avancharm.ir/wp-sitemap.xml` را ثبت کنید. Search Console و حساب cPanel در این مرحله متصل نیستند. امتیاز ۱۰۰ بخش SEO، بررسی‌های محدود خودکار لایت‌هاوس است و زمان ایندکس یا رتبهٔ گوگل را تضمین نمی‌کند.

## ابزارهای محتوا و بازگشت

از ریشهٔ وردپرس اجرا کنید؛ پورت `10046` مخصوص همین نصب محلی است و در هاست پارامتر آن را حذف کنید:

```powershell
php -d mysqli.default_port=10046 wp-content/themes/voiceweb/tools/audit-launch.php
php -d mysqli.default_port=10046 wp-content/themes/voiceweb/tools/prepare-launch-content.php
php -d mysqli.default_port=10046 wp-content/themes/voiceweb/tools/prepare-launch-content.php --apply
php -d mysqli.default_port=10046 wp-content/themes/voiceweb/tools/prepare-launch-indexing.php --apply
```

برای بازگرداندن متن قبلی محصولات، `prepare-launch-content.php --restore` اجرا می‌شود؛ این فرمان تغییرات متنی بعدی مدیر را نیز جایگزین می‌کند و باید فقط با قصد بازگشت استفاده شود. برای برگرداندن سیاست ایندکس نوشته‌های قدیمی، `prepare-launch-indexing.php --restore` وجود دارد. این ابزار را برای نوشته‌های تازهٔ نامرتبط به‌طور دوره‌ای اجرا نکنید؛ انتخاب‌هایش مخصوص آرشیو موجود هنگام این تحویل است.
