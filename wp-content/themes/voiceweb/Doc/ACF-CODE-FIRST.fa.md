# تعریف code-first گروه‌های ACF

گروه‌های اصلی ACF قالب داخل PHP تعریف می‌شوند تا schema همراه آپدیت قالب
به‌روز شود و به import، Sync یا migration دیتابیس نیاز نباشد.

## منابع تعریف

| کلید گروه | فایل |
|---|---|
| `group_home_blog` | `inc/acf-field-groups.php` |
| `group_cn_site_header_footer` | `inc/acf-field-groups.php` |
| `group_cn_term_icon` | `inc/acf-field-groups.php` |
| `group_voiceweb_front_page` | `inc/acf-field-groups.php` |

هر چهار گروه روی hook استاندارد `acf/include_fields` با تابع
`acf_add_local_field_group()` در `inc/acf-field-groups.php` ثبت می‌شوند.
سه گروه قدیمی با `cn_register_acf_field_groups()` و گروه صفحهٔ اصلی فروشگاه با
`voiceweb_register_front_page_fields()` در اولویت ۵ ثبت می‌شوند. گروه آیکون دسته
به فعال‌بودن API افزونهٔ Iconly وابسته است؛ بدون آن، سه گروه دیگر فعال می‌مانند.

```text
آپدیت قالب
    ↓
inc/acf-field-groups.php
    ↓
رجیستری Local PHP در ACF
    ↓
فرم‌ها با schema جدید
```

تعریف Local PHP در runtime بر رکورد هم‌کلید دیتابیس مقدم است. مقادیر واردشده
توسط مدیر همچنان در post meta، term meta یا options ذخیره می‌شوند و با آپدیت
schema حذف نمی‌شوند.

هیچ قفل سفارشی روی صفحهٔ **Custom Fields → Field Groups** اعمال نشده است.
رکوردهای دیتابیسی موجود و گروه‌های ساخته‌شده توسط توسعه‌دهندهٔ ثالث رفتار عادی
ACF را دارند. بااین‌حال منبع مؤثر چهار گروه هم‌کلید قالب، آرایهٔ PHP است.

پوشهٔ قدیمی `Doc/acf-import/` در ساختار فعلی وجود ندارد. چهار گروه اصلی قالب از PHP
ثبت می‌شوند؛ برای نصب یا آپدیت به JSON تاریخی یا import دستی نیاز نیست.

## صفحهٔ اصلی فروشگاه

گروه `group_voiceweb_front_page` با عنوان انگلیسی `Storefront homepage` فقط روی برگهٔ
ثابت انتخاب‌شده در **تنظیمات ← خواندن ← صفحهٔ اصلی** ظاهر می‌شود (`front_page`). این گروه
از schema مستقل برگهٔ نوشته‌ها (`group_home_blog`/`posts_page`) استفاده می‌کند؛ صفحهٔ
اصلی فروشگاه و آرشیو مجله می‌توانند همزمان تنظیمات جدا داشته باشند.

نام فیلدهای اصلی `vw_front_*` و کلیدها `field_vw_front_*` هستند. زیر‌فیلدهای repeater
کلید یکتای وابسته به بخش دارند، ولی نام ذخیرهٔ کوتاه مثل `title` یا `image` را حفظ می‌کنند.

| بخش | فیلدهای اصلی و قرارداد |
|---|---|
| اسلایدر | `slides` حداکثر ۶ ردیف؛ متن، تصویر دسکتاپ/موبایل، لینک اصلی/دوم، ترکیب رنگ و حداکثر ۳ تصویر شناور؛ `autoplay` پیش‌فرض خاموش، `interval` از ۵ تا ۲۰ ثانیه، پیش‌فرض ۸ |
| پیام هدر | `header_note` متن کوتاه اعلان |
| پیشنهاد ویژه | `offers_enabled/title/description/products/deadline`؛ انتخاب حداکثر ۱۲ محصول منتشرشده و زمان واقعی پایان تخفیف Woo |
| دسته‌بندی | `categories_enabled/title` و `categories` حداکثر ۱۲ کارت؛ term بومی `product_cat` الزامی، عنوان/توضیح/تصویر اختیاری |
| داستان و دربارهٔ ما | `story_*`، `about_*` و `collection_*` برای متن، تصویر و لینک هر بخش |
| کالکشن‌های منتخب | `promos` حداکثر ۲ کارت با متن، تصویر، لینک و ترکیب رنگ |
| تازه‌ها | `arrivals_enabled/title/products`، حداکثر ۱۲ محصول منتشرشده |
| مجله | `blog_enabled/title/description/posts`، حداکثر ۳ نوشتهٔ منتشرشده؛ `blog_link` لینک اختیاری آرشیو مجله، خالی به برگهٔ نوشته‌های وردپرس |
| ارزش‌های برند | `benefits` حداکثر ۴ ردیف با عنوان، توضیح و آیکون ثابت |
| پرسش‌های متداول | `faq_title` و `faq` حداکثر ۶ پرسش/پاسخ |

در جدول بالا پیشوند `vw_front_` برای اختصار حذف شده است. تصویرها attachment ID و
لینک‌ها array کامل `url/title/target` برمی‌گردانند. انتخاب محصول/نوشته نیز ID بومی است؛
قیمت، موجودی، تخفیف، variation و سفارش از ACF ساخته یا نگهداری نمی‌شوند.
انتخاب محصول خالی، انتخاب خودکار محصولات قابل نمایش را فعال می‌کند؛ ترتیب انتخاب صریح
با کشیدن محصولات تعیین می‌شود. ذخیرهٔ deadline آینده فقط برای محصولات انتخاب‌شده‌ای که
کاربر مجوز ویرایششان را دارد و قیمت تخفیف فعلی دارند، پایان تخفیف بومی را تنظیم می‌کند.
شمارنده از تاریخ واقعی تخفیف خوانده می‌شود و زمان ساختگی یا restart در هر بازدید ندارد.

label، instruction، choices و دکمهٔ افزودن انگلیسی در PHP باقی می‌مانند و از کاتالوگ
`languages/admin/fa_IR.po`/`en_US.po` ترجمه می‌شوند. نام/key فیلد، `ice/ink/rose` و دیگر
مقادیر ذخیره‌شونده ترجمه نمی‌شوند. فایل MO با ابزار موجود compile می‌شود.
جزئیات renderer، محتوا، طرح و ویرایش روزمره در [راهنمای صفحهٔ اصلی](./HOMEPAGE.fa.md) است.

## روش تغییر فیلدها

1. تعریف گروه را در فایل PHP منبع ویرایش کن.
2. `key` گروه و فیلدهای موجود را ثابت نگه دار.
3. برای حفظ داده‌های قبلی، `name` فیلد موجود را تغییر نده.
4. برای فیلد یا layout جدید یک `key` یکتا و پایدار بساز.
5. متن label و instructions را انگلیسی نگه دار و ترجمه را در کاتالوگ مدیریت
   قرار بده.
6. فایل را با `php -l` بررسی و فرم مقصد را تست کن.

تغییر label، instructions، ترتیب فیلد و location معمولاً migration نمی‌خواهد.
تغییر name یا نوع فیلد ممکن است با دادهٔ قبلی ناسازگار باشد و باید جداگانه بررسی
شود.

نام نمایشی layoutهای بلاگ بر اساس شکل نمایش کارت‌هاست، مانند کارت تصویری با
متن روی عکس، کارت عمودی، کارت افقی و کارت همراه ستون آخرین مطالب. کلیدها و
نام‌های ذخیره‌شوندهٔ قبلی (`featured`، `guide`، `hero`، `categories`،
`travelogue` و `news`) ثابت مانده‌اند.

عرض wrapper فیلدهای داخلی به‌صورت ۲۵، ۵۰، ۷۵ یا ۱۰۰ درصد مشخص شده است.
فایل `inc/admin.php` استایل `assets/css/admin/blog-editor.css` را فقط در
ویرایشگر برگه‌ها و پس از ACF بارگذاری می‌کند. این استایل به فیلد
`home_sections` با کلاس `cn-blog-sections` محدود است و در عرض‌های کوچک،
فیلدها را تک‌ستونی نمایش می‌دهد. سورس Sass آن در
`assets/scss/admin/blog-editor.scss` قرار دارد.

فیلدهای لینک باید `return_format=array` داشته باشند تا `url`، `title` و
`target` نگهداری شوند. بنر عریض و لینک مشترک «مشاهده بیشتر»، target انتخاب‌شده
را در HTML چاپ می‌کنند؛ `_blank` همراه `rel=noopener` نمایش داده می‌شود.

## تست سریع

```powershell
php -l wp-content/themes/voiceweb/inc/acf-field-groups.php
```

در runtime با ACF و Iconly فعال باید چهار کلید جدول بالا در `acf_get_local_field_groups()`
وجود داشته باشند و مقدار `local` آن‌ها `php` باشد. بدون Iconly، نبود گروه آیکون دسته
رفتار پیش‌بینی‌شده است. برگهٔ اصلی و برگهٔ نوشته‌ها را جداگانه باز کن تا location درست
گروه صفحهٔ فروشگاه و گروه مجله تأیید شود.
