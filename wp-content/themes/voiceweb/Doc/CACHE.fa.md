# کش مستقل فروشگاه — ۲۱ نوامبر ۲۰۲۶

[راهنمای اصلی](README.fa.md) · [انتشار در cPanel](LAUNCH.fa.md)

منطق کامل کش در **`wp-content/mu-plugins/voiceweb-cache.php`** قرار دارد. افزونهٔ کش دیگری، فایل `advanced-cache.php`، سرویس خارجی یا job زمان‌بندی‌شده برای آن نصب نشده است.

## قطع فوری با یک فایل

در File Manager سی‌پنل نام فایل را عوض کنید:

```text
wp-content/mu-plugins/voiceweb-cache.php
→ wp-content/mu-plugins/voiceweb-cache.php.disabled
```

کش HTML و نسخه‌گذاری اضافهٔ همین ماژول متوقف می‌شوند و وردپرس پاسخ معمولی می‌دهد. قوانین کش استاتیک و فشرده‌سازی VoiceWeb در `.htaccess` نیز به وجود همین فایل وابسته‌اند. برگرداندن نام، ماژول را دوباره فعال می‌کند. تنظیمات کش مستقل هاست یا CDN در اختیار این فایل نیستند؛ هنگام عیب‌یابی آن لایه را هم از کنترل‌پنل خودش پاک کنید. فایل‌هایی که قبلاً در مرورگر ذخیره شده‌اند با تغییر نام فایل از دستگاه بازدیدکننده حذف نمی‌شوند؛ برای بررسی از Hard Refresh استفاده کنید.

برای پاک‌سازی دستی بدون قطع ماژول، مدیر واردشده از نوار مدیریت **«پاک‌سازی کش فروشگاه»** استفاده کند. داده‌های کش در `wp-content/cache/voiceweb-pages/` تولید می‌شوند و نباید داخل Git یا بستهٔ انتقال قرار بگیرند. فایل‌های تولیدی با محافظ PHP شروع می‌شوند و درخواست مستقیم آن‌ها محتوا را نشان نمی‌دهد.

## چه چیزی ذخیره می‌شود؟

فقط HTML عمومیِ درخواست GET مهمان: خانه، فروشگاه، دسته، محصول، نوشته و برگه. اعتبار معمول حداکثر **۵ دقیقه** است و با نزدیک‌ترین شروع یا پایان تخفیف بومی ووکامرس کوتاه‌تر می‌شود. کش به دامنه، HTTPS، مسیر و زبان WPML وابسته است.

سبد، تسویه‌حساب، حساب کاربری، مدیریت، پیش‌نمایش، جست‌وجو، REST/AJAX، پاسخ خطا، فرم ارسالی، لینک دارای پارامتر عملیاتی و درخواست دارای cookie ورود/سبد/نشست ذخیره نمی‌شوند. هر cookie ناشناخته نیز برای احتیاط کش عمومی را دور می‌زند. پاسخ دارای `Set-Cookie`، `private` یا `no-store` ذخیره نمی‌شود. درخواست‌های تازه‌سازی قیمتِ شمارش معکوس هم از کش عبور نمی‌کنند.

## تازه‌شدن پس از تغییر

ذخیره یا حذف محصول/نوشته/برگه، متای محصول و ACF، دسته، فهرست، تنظیمات، موجودی، قیمت و نرخ دلار، به‌روزرسانی افزونه و تغییر قالب، نسل کش را نامعتبر می‌کند. تخلیه در انتهای درخواست انجام می‌شود تا ذخیرهٔ همهٔ فیلدها تمام شده باشد. قیمت‌گذاری گروهی بعد از `COMMIT` دیتابیس نیز hook جدا دارد. اولین بازدید بعدی، HTML جدید را می‌سازد؛ بازدیدهای بعدی همان نسخه را می‌گیرند. تغییر فایل‌های PHP/CSS/JS و فونت‌های قالب و چایلدتم نیز در امضای نسخه لحاظ می‌شود.

شروع و پایان زمان‌دار تخفیف حتی بدون بازکردن مدیریت، اعتبار HTML قبلی را تمام می‌کنند. قیمت نهایی از WooCommerce و منطق پایان تخفیف قالب خوانده می‌شود؛ قیمت یا موجودی داخل کش دوباره محاسبه یا تغییر داده نمی‌شود.

URL فایل‌های CSS/JS، فونت‌های لودر قالب و تصاویر و `srcset` رسانه با زمان تغییر فایل نسخه می‌گیرند. روی Apache/cPanel دارای ماژول‌های `headers`، `expires` و `deflate`، فایل‌های استاتیک هدر زیر دارند؛ HTML مرورگر همچنان باید با سرور بازاعتبارسنجی شود:

```http
Cache-Control: public, max-age=31536000, immutable
```

جایگزینی فایل‌های دستی خارج از لودر قالب، آدرس‌های ثابت داخل محتوای قدیمی، کش سرویس مستقل هاست و CDN باید جداگانه بررسی شوند. نصب هم‌زمان full-page cache دیگری توصیه نمی‌شود مگر قواعد دورزدن و پاک‌سازی آن نیز برای ووکامرس هماهنگ شود.

## بررسی و آزمون

```powershell
curl.exe -I https://avancharm.ir/
curl.exe -I https://avancharm.ir/wp-content/themes/voiceweb/assets/css/global.css
$env:VOICEWEB_WC_SITE='https://woo-charm-main.local'
$env:VOICEWEB_WC_MYSQL_PORT='10046'
node --use-system-ca wp-content/themes/voiceweb/tools/test-store-cache.cjs
```

برای صفحهٔ عمومیِ قابل کش، بار اول `X-VoiceWeb-Cache: MISS` و بار بعد `HIT` همراه `Age` دیده می‌شود. صفحهٔ خصوصی یا درخواست دورزننده نباید `HIT` باشد. آزمون خودکار با محصول موقت، برابری MISS/HIT، ویرایش محتوا و تنظیمات ACF، تغییر فایل قالب، دورزدن نشست‌ها، شروع و پایان واقعی sale، قطع فایل و هدر کش مرورگر، ذخیره هنگام قطع، فعال‌سازی دوباره و ثابت‌ماندن موجودی را بررسی کرده است؛ محصول موقت در پایان حذف می‌شود.

محیط Local این نصب، Nginx جلوی Apache دارد. ماژول‌های headers، expires، deflate و Brotli برای همین سایت محلی با backup پسوند `.voiceweb-launch-backup` در فایل تنظیمات runtime و `conf/apache/modules.conf.hbs` فعال شده‌اند. این فایل‌های محیطی وارد Git نمی‌شوند. Brotli برای مرورگر پشتیبان و gzip برای مرورگر دیگر به کار می‌رود. نسخهٔ HIT، تگ preload تصویر را پیش از ادامهٔ HTML ارسال می‌کند تا فشرده‌سازیِ کل صفحه شروع دانلود را عقب نیندازد؛ محتوای نهایی پاسخ یکسان است. دستورهای `.htaccess` را در cPanel واقعی نیز با هدر HTTP بررسی کنید؛ وجود فایل تنظیمات به‌تنهایی اثبات اعمال هدر نیست.
