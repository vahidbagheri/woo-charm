# طراحی فروشگاه کیف و چرم

تاریخ تغییر: ۱۴ اکتبر ۲۰۲۶. ظاهر فروشگاه از آبی به پس‌زمینهٔ کرم، سبز تیره و تصویرهای محصولات چرمی تغییر کرده است. اجرای صفحهٔ اصلی، ورود، درخواست تماس و دفترچهٔ آدرس راهنماهای جداگانه دارند؛ این سند بخش مشترک نمایش محصول و صفحات بومی ووکامرس را توضیح می‌دهد.

## کارت مشترک

در هر حلقهٔ ووکامرس، از override بسیار کوچک `woocommerce/content-product.php` به همان `template-parts/woocommerce/product-card.php` می‌رسیم. نسخهٔ قرارداد template در نصب WooCommerce 11.2.1 برابر `9.4.0` است و در header این override ثبت شده تا گزارش وضعیت ووکامرس تغییرات آینده را قابل بررسی کند. صفحهٔ اصلی هم می‌تواند آن را در `ul.products.vw-product-grid` با `args['product']` از نوع `WC_Product` رندر کند.

کارت متغیرهای سراسری `post` و `product` را موقتاً روی محصول قرار می‌دهد و بعد از رندر به مقادیر قبل برمی‌گرداند. بنابراین عنوان کارت در صفحهٔ اصلی، عنوان همان محصول است. visibility، کلاس‌های استاندارد، آدرس محصول، قیمت و currency از خود ووکامرس خوانده می‌شوند.

تمام hookهای استاندارد حلقه به ترتیب حفظ شده‌اند:

1. `woocommerce_before_shop_loop_item`
2. `woocommerce_before_shop_loop_item_title`
3. `woocommerce_shop_loop_item_title`
4. `woocommerce_after_shop_loop_item_title`
5. `woocommerce_after_shop_loop_item`

دکمهٔ ساده همان `add_to_cart_button ajax_add_to_cart` بومی است؛ لینک انتخاب گزینه‌ها برای محصول متغیر باقی مانده است. در حالت درخواست تماس، فیلتر قابلیت درخواست تماس همان خروجی native را جایگزین می‌کند. تصاویر با API رسانهٔ ووکامرس و اندازه‌های وردپرس رندر می‌شوند. عکس روی کارت مربع، با گوشهٔ نرم و بزرگ‌نمایی بسیار کم در hover است. در موبایل شبکه دو ستون می‌ماند و کارت به عرض صفحه فشار نمی‌آورد.

دکمهٔ خرید/انتخاب گزینه‌ها در کنار قیمت به شکل دایرهٔ ۴۴px نمایش داده می‌شود. آیکون کیف برای خرید ساده و فلش برای انتخاب گزینه‌ها/مشاهدهٔ محصول است. `href`، `data-product_id`، کلاس‌های AJAX و توضیح قابل دسترس native حفظ شده‌اند و label متنی برای screen reader در markup باقی می‌ماند. کنترل‌های rich افزونه‌های دیگر که markup متفاوت دارند دست‌نخورده می‌مانند. دکمهٔ درخواست تماس همچنان متن قابل خواندن دارد.

رنگ‌های کارت از taxonomy واقعی `pa_color` و meta رسمی افزونهٔ Variation Swatches یعنی `product_attribute_color` خوانده و با `sanitize_hex_color` اعتبارسنجی می‌شوند. چهار رنگ و تعداد باقی‌مانده نمایش داده می‌شود. این نقطه‌ها پیش‌نمایش‌اند؛ انتخاب واقعی رنگ در فرم native محصول انجام می‌شود. نام رنگ برای فناوری کمکی در markup حضور دارد.

## قیمت و تخفیف

هیچ قیمت، واحد پول یا درصد ساختگی در قالب وجود ندارد. قیمت از template و API خود ووکامرس می‌آید. badge ساده درصد کاهش regular به sale همان محصول را نشان می‌دهد. برای محصول متغیر، جفت قیمت‌های هر variation جداگانه مقایسه می‌شوند و بیشترین درصد با عبارت «تا» نمایش داده می‌شود؛ regular یک variation با sale variation دیگری ترکیب نمی‌شود.

محصولی که واقعاً on-sale نیست، badge تخفیف درصدی نمی‌گیرد. مبلغ فروش، مالیات، موجودی و سفارش همچنان توسط ووکامرس محاسبه می‌شوند.

## صفحهٔ محصول و تایمر واقعی

گالری native ووکامرس، zoom، lightbox، thumbnailها، فرم خرید، tabهای توضیح/مشخصات/نظرات و related products حفظ شده‌اند. قالب جدید دو ستون در دسکتاپ و یک ستون در موبایل دارد؛ وضعیت موجودی، قیمت، دسته، فرم گزینه‌ها و دکمهٔ اصلی قابل دیدن‌اند. عکس‌های اضافی thumbnailهای قابل پیمایش دارند.

تایمر محصول ساده فقط وقتی نشان داده می‌شود که تخفیف فعال و `get_date_on_sale_to()` در آینده باشد. متن زمان پایان هنگام نبود JavaScript از `<noscript>` قابل خواندن است. زمان صفر شود، پنل پنهان می‌شود و شمارنده از ابتدا راه نمی‌افتد.

برای متغیر، hook `woocommerce_available_variation` مقدار `voiceweb_sale_deadline` را روی دادهٔ همان variation می‌گذارد. رویداد native `found_variation` تایمر را برای گزینهٔ انتخاب‌شده نشان می‌دهد؛ انتخاب گزینهٔ بدون پایان تخفیف و `reset_data` / `hide_variation` آن را پنهان می‌کند. انتخاب پیش‌فرضی که قبل از script deferred حل شده باشد نیز از دادهٔ native فرم خوانده می‌شود. صرفاً این نمایش تغییر می‌کند؛ تایمر قیمت سمت سرور را تغییر نمی‌دهد.

صفحه‌ای که هنگام پایان تخفیف باز مانده، قیمت قبلی را صرفاً با پنهان‌شدن
شمارنده نگه نمی‌دارد. وقتی deadline مثبت داریم، یک HEAD خواندنی به URL
canonical همان origin، Date سرور را می‌گیرد؛ تصمیم پایان تا نتیجهٔ ساعت
سرور صبر می‌کند. این کار ساعت نادرست دستگاه را جبران می‌کند. بدون deadline
مثبت، این مسیر فعال نمی‌شود؛ قبل از پایان فروش هفت‌روزه GET تازه‌کردن قیمت
انجام نمی‌شود.

بعد از گذشت timestamp واقعی و حاشیهٔ ۱۱۰۰ms برای ثانیهٔ پایانی inclusive
ووکامرس، یک GET `no-store` به صفحهٔ عمومی با timeout دوازده‌ثانیه‌ای و
cache-buster `vw_price_refresh` انجام می‌شود. پارامترهای اقدام مثل
`add-to-cart` از URL کنار گذاشته می‌شوند تا قیمت‌خوانی دوباره خرید را اجرا
نکند. product ID، DOM محصول و دادهٔ native فرم با صفحهٔ فعلی تطبیق داده
می‌شوند؛ HTML یا variation JSON دارای deadline مثبتِ ازقبل‌گذشته به‌عنوان
cache منقضی رد می‌شود و قبل از اعتبارسنجی قیمت روی صفحه نوشته نمی‌شود.

قیمت مستقیم `.summary > .price` و badge اصلی `onsale` از HTML معتبر تازه
گرفته می‌شوند. در متغیر، `data-product_variations` و cache متناظر jQuery
به‌روز و رویداد native `reload_product_variations` اجرا می‌شود؛ handler
خود ووکامرس دادهٔ داخلی `variationData/useAjax` را تازه و سپس
`check_variations` را اجرا می‌کند. فرم، selectها، swatchها و مقدار انتخاب
مشتری جایگزین نمی‌شوند. تغییر تصویر/قیمت/موجودی همان رویدادهای بومی را دارد.
پاسخ `false` برای حالت AJAX variation نیز به‌عنوان حالت معتبر native حفظ
می‌شود. event `voiceweb:product-price-updated` پس از موفقیت منتشر می‌شود.

این GET برای هر deadline یک بار برنامه‌ریزی می‌شود؛ `pagehide` timerهای
منتظر را جمع می‌کند و در بازگشت bfcache شمارنده بازبینی می‌شود. خطای شبکه
یا پاسخ cache نامعتبر، پیام کوتاه بازکردن دوبارهٔ صفحه را نشان می‌دهد.
قیمت مالی، سبد، سفارش و stock را این JavaScript تعیین نمی‌کند؛ قیمت native
در خرید دوباره بررسی می‌شود. برای اصلاح cache و lookup سمت سرور،
[راهنمای پایان تخفیف](./SALE-EXPIRY.fa.md) را ببین.

افزونهٔ نصب‌شدهٔ `woo-variation-swatches` گزینه‌های رنگ/اندازه را به فرم native وصل می‌کند. فرم بازنویسی نشده است. نمایش رنگ انتخاب‌شده، variation ID، عکس/قیمت/موجودی و اعتبارسنجی native حفظ می‌شود. اگر افزونه غیرفعال شود، selectهای معمول ووکامرس همچنان کار می‌کنند.

## علاقه‌مندی‌ها

برای محصول ساده، دکمهٔ قلب کارت همان Store API بومی WooCommerce Wishlists را استفاده می‌کند. script حالا به تمام دکمه‌های صفحه وصل می‌شود و نتیجهٔ یک تغییر را روی تمام کنترل‌های همان product ID بازتاب می‌دهد. صفحه پس از `voiceweb:catalog-updated` هم دوباره متصل می‌شود و دکمه‌های حذف‌شدهٔ DOM نگه داشته نمی‌شوند.

یک درخواست اولیهٔ مشترک فهرست را می‌خواند؛ نوشتن‌ها به ترتیب انجام می‌شوند و timeout بیست‌ثانیه‌ای، refreshed nonce، پاسخ DELETE با وضعیت ۲۰۴ و خطای شبکه پوشش داده شده‌اند. REST جدید یا جدول دیگری برای علاقه‌مندی ساخته نشده است؛ مالکیت و امنیت همچنان متعلق به Store API بومی است.

قلب محصول متغیر در کارت به `#vw-product-options` می‌رود تا مشتری ابتدا گزینهٔ واقعی را انتخاب کند. دکمهٔ صفحهٔ محصول variation انتخاب‌شده را ذخیره می‌کند. مهمان با قلب محصول ساده به مودال ورود می‌رود و سپس به همان محصول برمی‌گردد. قابلیت native Wishlists باید در تنظیمات ووکامرس روشن باشد؛ قالب آن را در هر درخواست فعال نمی‌کند.

## سبد، حساب و پرداخت

بلوک‌های واقعی Cart و Checkout در صفحات موجود باقی مانده‌اند. رنگ دکمه‌ها، فیلدها، خلاصه سفارش، coupon، روش ارسال/پرداخت، موجودی و تصاویر با طرح جدید هماهنگ است. در عرض‌های پایین ستون‌ها به ترتیب native روی هم قرار می‌گیرند. فرم‌ها حداقل ارتفاع مناسب لمس دارند و input متنی موبایل ۱۶px است تا zoom ناخواستهٔ iOS کم شود.

حساب کاربری، سفارش‌ها، علاقه‌مندی‌ها، دفترچهٔ چندآدرسی و دیالوگ ثبت/ویرایش آدرس همان جریان قبلی را دارند. رنگ‌های آبی hardcoded پنل‌ها و دیالوگ فیلتر به رنگ‌های کرم/سبز تغییر کرده است. در موبایل منوی حساب عمودی باقی می‌ماند؛ اسلایدر افقی برای آن اضافه نشده است. خطا، وضعیت ناموفق و هشدار پرداخت همچنان رنگ معنایی مناسب دارند.

در `order-pay` آدرس snapshot همان سفارش و بررسی مالکیت/کلید ووکامرس حفظ می‌شود. این تغییر ظاهری، وضعیت سفارش، stock، روش درگاه، درخواست واقعی پرداخت یا دادهٔ سفارش موجود را تغییر نمی‌دهد. قالب از رنگ و کلاس صفحات native استفاده می‌کند و افزونه‌های پرداخت مستقل باقی می‌مانند.

## توسعه و بررسی

Sassهای entry را بعد از تغییر partialها با Sass موجود کامپایل کنید؛ فایل CSS خروجی هم باید همراه منبع ذخیره شود. build بقیهٔ theme و [راهنمای اجرا](./RUNBOOK.fa.md) را ببینید. افزونهٔ درخواست تماس [راهنمای جدا](./INQUIRIES.fa.md) دارد؛ برای قرارداد آدرس، order-pay، امنیت و native Wishlist به [راهنمای ووکامرس](./WOOCOMMERCE.fa.md) مراجعه کنید.

آزمون `test-product-design-browser.cjs` مشتری/محصول/variation/dستهٔ موقت می‌سازد، پیامک را در مرورگر مسدود می‌کند، خرید واقعی یا ثبت سفارش انجام نمی‌دهد و fixtures را در `finally` پاک می‌کند. این آزمون روی محیط توسعه اجرا شود. تست قدیمی `test-account-menu-browser.cjs` به‌خاطر وجود قلب‌های محصولات مرتبط، selector علاقه‌مندی صفحهٔ محصول را به `.summary [data-vw-wishlist-product]` محدود کرده است.

این آزمون اختصاصی در ۱۴ اکتبر ۲۰۲۶ روی نصب محلی موفق بود: بازگرداندن globalها، درصد تخفیف متغیر، چند دکمهٔ علاقه‌مندی، افزودن AJAX، بارگذاری بلوک‌های سبد و تسویه‌حساب، پایان واقعی تایمر و تایمر مستقل variation و عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ بررسی شد. خطای JavaScript، پیامک واقعی، پرداخت و سفارش ثبت‌شده صفر بود. ممیزی پس از اجرا نیز محصول، کاربر و دستهٔ fixture باقی‌مانده را صفر نشان داد. عکس‌های تست در پوشهٔ موقت سیستم هستند و جزء محتوای واقعی فروشگاه نیستند.

پس از هماهنگی ارتفاع هدر و دکمهٔ گرد کارت، آزمون محصول تکرار و موفق شد. آزمون منوی حساب نیز ورود مهمان، disclosure و کیبورد، حذف علاقه‌مندی با ۲۰۴، گزینهٔ متغیر، جداسازی دو مالک، nonce و موبایل را با صفر خطای JavaScript تأیید کرد. سقف قیمت hardcoded آزمون کاتالوگ قبلی برای فروشگاه تک‌محصولی بود؛ اکنون bound عمومی قبل از افزودن fixtureهای private ثبت و hidden/draftهایی با قیمت بالاتر اضافه می‌شوند تا مستقل از قیمت محصولات واقعی، عدم ورود قیمت خصوصی به بازه آزموده شود.

آزمون کاتالوگ به‌روز نیز موفق شد: بازه، مرتب‌سازی، دسته، برند، ویژگی، محصول متغیر، موجودی/حراج/امتیاز/جستجو، صفحه‌بندی، back/forward، اعمال/لغو موبایل، retry خطای شبکه، حالت بدون JavaScript و عرض ۳۲۰ بررسی شدند. خطای JavaScript و سفارش ساخته‌شده صفر بود.

آزمون `test-product-price-expiry-browser.cjs` هم روی مرز **واقعی شش‌ثانیه‌ای**
sale موفق شد. ابتدا محصول هفت‌روز فعال و محصول بدون sale با ساعت دستگاه
هشت‌روز جلوتر باز شدند و GET قیمت صفر بود؛ سپس پایان واقعی از PHP/Woo
تنظیم و HTML سرور reload شد، بدون دستکاری DOM زمان/قیمت. پس از پایان،
محصول ساده قیمت regular گرفت؛ summary، قیمت گزینه، attribute JSON و cache
jQuery متغیر تازه شدند. فرم و quantity/selection محفوظ ماندند و انتخاب
variation دیگر قیمت regular درست را نشان داد. دقیقاً یک GET برای ساده و
یکی برای متغیر ثبت شد؛ stock، سفارش، پیامک، پرداخت و خطای JavaScript صفر
تغییر/ثبت داشتند. کاربر/محصولهای موقت، actionهای زمان‌بندی‌شدهٔ خود fixture
و guard اختصاصی پس از تست پاک می‌شوند؛ تست فقط روی محیط توسعه اجرا شود.

```powershell
node wp-content/themes/voiceweb/tools/test-product-price-expiry-browser.cjs
```

متغیرهای session اجرای آن همان `VOICEWEB_WC_SITE`، `VOICEWEB_WC_MYSQL_PORT`،
`VOICEWEB_PHP`، `VOICEWEB_PLAYWRIGHT_PATH` و `VOICEWEB_BROWSER_EXECUTABLE`
در [راهنمای اجرا](./RUNBOOK.fa.md) هستند.
